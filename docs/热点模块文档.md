# 热点模块文档

## 一、模块概述

热点监控模块提供热点数据抓取和 AI 分析功能，通过集成多个 AI 模型（DeepSeek、Kimi、Doubao等），为用户提供智能化的热点分析和内容创作建议。

### 核心功能
- **热点抓取**：从各大平台（微博、知乎、抖音、百度等）采集热点数据
- **AI 分析**：使用指定的 AI 模型对热点进行深度分析
- **缓存机制**：支持热点数据和 AI 分析结果的 Redis 缓存
- **历史记录**：保存关键词使用历史和热点分析记录

## 二、接口设计

### 2.1 POST /list - 热点抓取（基础版）

**接口地址：** `POST /ai-generated-articles/hotspot/list`

**功能说明：** 仅从各大平台抓取热点数据，不进行 AI 分析

**请求参数：**
```json
{
  "keyword": "人工智能，AI 技术"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | String | 是 | 热点关键词，多个用逗号分隔 |

**详细步骤说明：**

1. **解析关键词**
   - 从 requestDTO 获取 keyword 参数
   - 按逗号分割成关键词列表

2. **生成请求标识**
   - `requestNo`：唯一请求编号（时间戳 + UUID）
   - `requestHash`：基于关键词的哈希值（用于缓存）

3. **检查缓存**
   - 根据 requestHash 查询 Redis 缓存
   - ✅ 缓存命中 → 直接返回缓存结果
   - ❌ 缓存未命中 → 继续执行

4. **创建数据库记录**
   - 类型：KEYWORD
   - 状态：INIT
   - 保存 inputPayload（请求参数 JSON）

5. **调用全网采集服务**
   - UniversalHotspotService.fetchHotspots()
   - 调用百度千帆 AI Search API
   - 返回原始热点数据列表

6. **转换为 VO 对象**
   - RawHotspotItem → HotspotInfoVO
   - 计算热度值
   - AI 分析字段留空

7. **更新数据库记录**
   - 状态：SUCCESS
   - 保存 resultJson

8. **写入缓存**
   - 默认 TTL（未指定）

9. **保存关键词历史**
   - 累加使用次数

10. **返回结果**

**响应示例：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "hotList": [
      {
        "index": 1,
        "title": "AI 技术新突破",
        "content": "最新的人工智能技术在多个领域取得重要进展...",
        "source": "知乎",
        "heat": 98500
      }
    ],
    "coreOpinionList": [],
    "controversialPerspectiveList": [],
    "writingGuidanceList": {
      "themes": [],
      "examples": []
    }
  },
  "requestId": "xxx",
  "timestamp": "2026-03-13 14:00:00"
}
```

### 2.2 POST /analyze-with-ai - 热点抓取 + AI 分析（完整版）

**接口地址：** `POST /ai-generated-articles/hotspot/analyze-with-ai`

**功能说明：** 从各大平台抓取热点数据并使用指定 AI 模型进行分析

**请求参数：**
```json
{
  "keyword": "人工智能，AI 技术",
  "modelType": "DEEPSEEK"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | String | 是 | 热点关键词，多个用逗号分隔 |
| modelType | String | 否 | AI 模型类型，默认 DEEPSEEK<br>可选：DEEPSEEK, KIMI, DOUBAO, QWEN |

**处理流程：**

**详细步骤说明：**

1. **解析关键词**
   - 从 requestDTO 获取 keyword 参数
   - 按逗号分割成关键词列表

2. **获取 AI 模型类型**
   - 从 requestDTO 获取 modelType
   - 默认：DEEPSEEK
   - 可选：KIMI, DOUBAO, QWEN

3. **生成请求标识**
   - `requestNo`：唯一请求编号
   - `requestHash`：基于关键词 + 模型类型的哈希值

4. **检查缓存**
   - 根据 modelType + requestHash 查询 Redis
   - ✅ 缓存命中 → 直接返回（AI 分析结果缓存 1 小时）
   - ❌ 缓存未命中 → 继续执行

5. **创建数据库记录**
   - 类型：KEYWORD_AI
   - 状态：INIT
   - 设置 sourcePlatforms: ["BAIDU"]
   - 保存 inputPayload（包含 modelType）

6. **调用全网采集服务**
   - UniversalHotspotService.fetchHotspots()
   - 与接口 1 相同

7. **调用 AI 协调器进行分析 ⭐ 核心步骤**
   - AiModelCoordinator.analyze()
   - 根据 modelType 选择合适的 AI 服务
   - 构造分析 Prompt
   - 调用对应 AI API（DeepSeek/Kimi/Doubao）
   - 返回 AI 分析文本

8. **转换为 VO 对象**
   - RawHotspotItem → HotspotInfoVO
   - AI 分析结果保存到相关字段

9. **更新数据库记录**
   - 状态：SUCCESS
   - 保存 resultJson

10. **写入缓存**
    - TTL: 60 分钟（AI 分析结果）

11. **保存关键词历史**

12. **返回结果（包含 AI 分析）**

**AI 分析详细流程（第 7 步）：**

**Prompt 构造：**
```
你是一位专业的热点分析师。请根据以下热点数据进行深度分析：

搜索关键词：{keywords}

热点列表：
{热点数据，最多 10 条}

请从以下维度进行分析：
1. 核心话题：总结这些热点反映的主要社会话题或趋势
2. 关键观点：提取各方立场和核心观点
3. 争议焦点：识别存在争议的方面
4. 写作建议：为内容创作者提供选题方向和写作建议

要求：
- 分析要客观、全面
- 观点要清晰、有深度
- 建议要具体、可操作
- 字数控制在 800-1500 字
```

**API 调用细节：**
- 发送 HTTP POST 请求
- 设置 Content-Length 头
- 携带 Authorization Token
- 解析响应：`choices[0].message.content`

**响应示例：**

### 2.3 POST /analyze - 热点深度分析（已实现 ✅）

**接口地址：** `POST /ai-generated-articles/hotspot/analyze`

**功能说明：** 对已有的热点数据进行深度分析（不需要重新抓取）

**请求参数：**
```json
{
  "hotList": [
    {
      "index": 1,
      "title": "AI 技术新突破",
      "content": "最新的人工智能技术在多个领域取得重要进展...",
      "source": "知乎",
      "publishTime": "2026-03-13 10:00:00",
      "likeCount": 1000,
      "commentCount": 200,
      "shareCount": 150
    },
    {
      "index": 2,
      "title": "机器学习应用案例",
      "content": "机器学习在医疗、金融等领域的成功应用...",
      "source": "微博",
      "publishTime": "2026-03-13 11:00:00",
      "likeCount": 800,
      "commentCount": 150,
      "shareCount": 100
    }
  ],
  "modelType": "DEEPSEEK"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| hotList | Array | 是 | 待分析的热点列表 |
| hotList[].index | Integer | 是 | 热点序号 |
| hotList[].title | String | 是 | 热点标题 |
| hotList[].content | String | 是 | 热点内容描述 |
| hotList[].source | String | 是 | 热点来源平台 |
| hotList[].publishTime | String | 否 | 发布时间（格式：yyyy-MM-dd HH:mm:ss） |
| hotList[].likeCount | Long | 否 | 点赞数（用于计算热度，未提供则使用固定值 1000） |
| hotList[].commentCount | Long | 否 | 评论数（用于计算热度） |
| hotList[].shareCount | Long | 否 | 转发数（用于计算热度） |
| modelType | String | 否 | AI 模型类型，默认 DEEPSEEK<br>可选：DEEPSEEK, KIMI, DOUBAO |

**处理流程：**

**详细步骤说明：**

1. **获取 AI 模型类型**
   - 从 requestDTO 获取 modelType
   - 默认：DEEPSEEK
   - 可选：KIMI, DOUBAO

2. **生成请求标识**
   - `requestNo`：唯一请求编号
   - `requestHash`：基于 hotList 内容 + modelType 的哈希值

3. **检查缓存**
   - 根据 modelType + requestHash 查询 Redis
   - ✅ 缓存命中 → 直接返回（AI 分析结果缓存 1 小时）
   - ❌ 缓存未命中 → 继续执行

4. **创建数据库记录**
   - 类型：RAW_LIST_AI（新增）
   - 状态：INIT
   - 设置 sourcePlatforms: ["USER_PROVIDED"]
   - 保存 inputPayload（包含完整请求 JSON）

5. **转换 DTO 为内部对象**
   - HotspotSourceDTO → RawHotspotItem
   - 补充缺失字段：
     - url: ""
     - publishTime: 解析或当前时间
     - likeCount/commentCount/shareCount: 使用提供的值或 0
     - platformType: "USER_PROVIDED"

6. **调用 AI 协调器进行分析**
   - AiModelCoordinator.analyze()
   - 提取关键词（取前 3 个热点标题的前 20 字）
   - 根据 modelType 选择合适的 AI 服务
   - 构造 JSON 格式 Prompt
   - 调用对应 AI API
   - 返回 AI 分析文本（JSON 格式）

7. **解析 AI 分析结果 ⭐**

   - 提取 coreOpinionList（核心观点）
   - 提取 controversialPerspectiveList（争议视角）

8. **转换为 VO 对象**
   - RawHotspotItem → HotspotInfoVO
   - 热度计算：用户提供的数据使用固定值 1000
   - 合并 AI 分析结果

9. **更新数据库记录**
   - 状态：SUCCESS
   - 保存 resultJson

10. **写入缓存**
    - TTL: 60 分钟

11. **返回结果（包含 AI 分析）**

## 三、核心组件说明

### 3.1 UniversalHotspotService（全网采集服务）

**职责：** 统一调用百度千帆 AI Search API

**方法：** `fetchHotspots(List<String> keywords)`

**流程：**
1. 构造 Prompt（要求返回 JSON 格式的热点数据）
2. 调用百度千帆 API
3. 解析响应，提取 JSON 数组
4. 转换为 `RawHotspotItem` 对象列表

**配置参数：**
```properties
baidu.qianfan.api-key=your-api-key
baidu.qianfan.base-url=https://qianfan.baidubce.com/v2
baidu.qianfan.model=ernie-4.5-turbo-32k
```

---

### 3.2 AiModelCoordinator（AI 模型协调器）

**职责：** 根据 modelType 分发到不同的 AI 服务

**方法：** 
- `analyze(String modelType, List<String> keywords, List<RawHotspotItem> hotspots)`
- `getAvailableModels()` - 获取所有可用的 AI 模型类型

**策略模式：** 自动选择支持的 AiModelService

---

### 3.3 AiModelService（AI 模型服务接口）

**接口定义：**
```java
public interface AiModelService {
    boolean supports(String modelType);
    String analyze(List<String> keywords, List<RawHotspotItem> hotspots);
    String getModelType();
}
```

**实现类：**

| 实现类 | 支持的模型 | API 提供商 |
|--------|-----------|-----------|
| DeepSeekAiService | DEEPSEEK | 深度求索 |
| KimiAiService | KIMI | 月之暗面 |
| DoubaoAiService | DOUBAO | 字节跳动 |

**共同方法：** `analyze(keywords, hotspots)`

**实现差异：** 各自调用不同的 API 端点和认证方式

**配置参数：**
```properties
# DeepSeek
deepseek.api-key=sk-your-api-key
deepseek.base-url=https://api.deepseek.com/v1
deepseek.model=deepseek-chat

# Kimi
kimi.api-key=sk-your-kimi-api-key
kimi.base-url=https://api.moonshot.cn/v1
kimi.model=moonshot-v1-8k

# Doubao
doubao.api-key=your-doubao-api-key
doubao.base-url=https://ark.cn-beijing.volces.com/api/v3
doubao.model=doubao-pro-32k
```

---

### 3.4 HotspotCacheService（热点缓存服务）

**职责：** 管理 Redis 缓存

**两种缓存：**

1. **普通热点缓存**（/list 接口）
   - Key 格式：`hotspot:list:{requestHash}`
   - TTL：默认（未指定）

2. **AI 分析缓存**（/analyze-with-ai 接口）
   - Key 格式：`hotspot:ai:{modelType}:{requestHash}`
   - TTL：60 分钟

**方法：**
- `getFromCache(String cacheKey)` - 从缓存获取
- `saveToCache(String cacheKey, HotspotAnalysisResultVO resultVO)` - 保存到缓存
- `saveToCache(String cacheKey, HotspotAnalysisResultVO resultVO, Long ttlMinutes)` - 指定 TTL

---

### 3.5 HotspotAnalysisRecordService（数据库记录服务）

**职责：** 管理热点分析记录的持久化

**功能：**
- `createRecord(HotspotAnalysisRecordEntity entity)` - 创建记录
- `markSuccess(Long id, String resultJson, LocalDateTime finishedTime)` - 标记成功
- `markFailed(Long id, String errorMessage, LocalDateTime finishedTime)` - 标记失败
- `getById(Long id)` - 根据 ID 查询
- `getByRequestNo(String requestNo)` - 根据请求号查询
- `getLatestSuccessByRequestHash(String requestHash)` - 根据哈希查询最近成功记录

**实体结构：**
```java
HotspotAnalysisRecordEntity {
    Long id;                    // 主键 ID
    String requestNo;           // 请求流水号
    Long userId;                // 用户 ID（默认 -1）
    String requestType;         // KEYWORD / KEYWORD_AI
    String keyword;             // 热点关键词
    String requestHash;         // 请求摘要哈希
    String sourcePlatforms;     // 抓取平台列表 JSON
    String inputPayload;        // 原始请求报文 JSON
    String status;              // INIT / SUCCESS / FAILED
    String resultJson;          // 热点分析结果 JSON
    String errorMessage;        // 失败原因
    LocalDateTime startedTime;  // 开始处理时间
    LocalDateTime finishedTime; // 处理完成时间
}
```

---

### 3.6 HotspotKeywordHistoryService（关键词历史服务）

**职责：** 保存和管理用户使用的关键词历史

**功能：**
- `saveOrIncrement(Long userId, String keyword, LocalDateTime lastUsedTime)` - 保存或累加使用次数
- `listLatestByUserId(Long userId, Integer limit)` - 查询用户最近的关键词

**实体结构：**
```java
HotspotKeywordHistoryEntity {
    Long id;                    // 主键 ID
    Long userId;                // 用户 ID
    String keyword;             // 关键词
    Integer usedCount;          // 使用次数
    LocalDateTime lastUsedTime; // 最近使用时间
}
```

## 六、热度计算算法

```java
private Integer calculateHeat(RawHotspotItem item) {
    long heat = 0;
    if (item.getLikeCount() != null) heat += item.getLikeCount();
    if (item.getCommentCount() != null) heat += item.getCommentCount() * 2;
    if (item.getShareCount() != null) heat += item.getShareCount() * 3;
    if (item.getSearchIndex() != null) heat += item.getSearchIndex();
    return Math.min((int) heat, 100000); // 限制最大值 100000
}
```

**权重说明：**
- 点赞数：1x
- 评论数：2x
- 分享数：3x
- 搜索指数：1x

## 十三、常见问题（FAQ）

### Q1: 为什么调用接口返回 411 错误？

**A:** 百度千帆 API 要求必须提供 Content-Length 请求头。代码中已设置该请求头，如果遇到此错误，请确保：
1. 应用已重新启动
2. 代码已重新编译（执行 `mvn clean install`）

### Q2: 为什么返回 "inputPayload must not be blank" 错误？

**A:** 这是数据库记录服务的验证逻辑。已在 Controller 中修复，将 requestDTO 序列化为 JSON 字符串并赋值给 inputPayload。

### Q3: AI 分析结果为什么是空的？

**A:** v1.1.0 之前版本中，AI 分析文本没有被解析成结构化数据。v1.1.0 已修复此问题，现在 AI 会返回 JSON 格式的结构化分析结果。

### Q4: 如何切换 AI 模型？

**A:** 在请求中指定 modelType 参数：
- `/list` 接口：不支持 modelType
- `/analyze-with-ai` 接口：`{"modelType": "DEEPSEEK"}`
- `/analyze` 接口：`{"modelType": "DEEPSEEK"}`

可选值：DEEPSEEK, KIMI, DOUBAO

### Q5: 缓存多久过期？

**A:** 
- 普通热点缓存（/list）：默认 TTL（未指定，由 Redis 决定）
- AI 分析缓存（/analyze-with-ai）：60 分钟
- 深度分析缓存（/analyze）：60 分钟

### Q6: /analyze 接口和 /analyze-with-ai 有什么区别？

**A:** 
- **数据来源不同**：
  - `/analyze-with-ai`：从百度千帆 API 实时抓取热点数据
  - `/analyze`：使用用户提供的热点数据

- **适用场景不同**：
  - `/analyze-with-ai`：需要获取最新热点时
  - `/analyze`：已有热点数据，只需进行分析时

- **请求参数不同**：
  - `/analyze-with-ai`：需要提供 keyword（关键词）
  - `/analyze`：需要提供 hotList（热点列表）

### Q7: 用户提供的数据热度值如何计算？

**A:** 
- 如果提供了 likeCount/commentCount/shareCount：按权重计算
  - 点赞数：1x
  - 评论数：2x
  - 转发数：3x
  - 搜索指数：1x
  - 最大值限制：100000

- 如果未提供互动数据：使用固定值 **1000**
